# 董事会裁定：暂停审计认证链，转入 P0 改造

- 版本：0.1.0
- 日期：2026-09-03
- 裁定人：董事会（用户）
- 裁定原话：**「B」**（对「路线 A 走完认证链 / 路线 B 接受现有结论转去修问题」的选择）
- 生效范围：审计治理流程与改造启动顺序。**不改变任何已登记的技术结论。**

## 1. 裁定内容

董事会选择**路线 B**：

1. **接受现有 26 项问题清单**（P0 8、P1 11、P2 7）作为改造输入；
2. **明示接受其验证等级为 E1**（静态代码、配置、数据库只读观察）；
3. **暂停 A0–A6 与 R0 的认证链**，不再以「阶段正式通过」为改造前置条件；
4. **改造工作即刻开始**，按 P0 优先级推进。

## 2. 为什么这不是跳过

审计要回答的问题是「系统哪里有问题」。**这个问题已经答完了**：
26 项问题各有编号、根因、代码位置、证据等级与最小后续验证方法，
经八轮异源复核、累计推翻主审 24 条实质结论后固化。

认证链剩余部分（AG-01~AG-05、A1–A6 逐阶段再批准、R0 补证）**证明的是审计过程合规**，
不是系统状态。**这些技术结论不因缺少合格证而失真。**

墙钟：2026-09-25 到期，裁定日剩 22 天。经评估，认证链无法在期限内走完
（仅 R0 的 D-01/D-02/D-05/D-06/D-07 五域仍停在第一轮首屏发现）。
在「拿到合格证」与「修好问题」之间，董事会选择后者。

|---|---|

本裁定**不解除任何技术门禁**，只解除「改造必须等认证链走完」这一流程前置。

## 4. 重启条件

出现下列任一情形时，认证链应当重启，且从 AG-02 开始：

1. 本材料需要对外用于投标、尽调、认证或合规审查；
2. 出现真机（E3）或课堂（E4）交付需求；
3. 董事会认为改造结论的可信度需要独立背书。

重启时 A0–A6 的现有材料仍然有效，作为重开的起点而非重做的对象。

M-DEC-02 的返工阈值为「任一代码任务缺少上层批准依据即不得进入实施」。

路线 B 下已执行的 9 批代码改造**无上层 R1 目标架构批准依据**，属逆序执行。
这是路线 B 裁定的直接后果，非擅自越界，但**指令层面需明示豁免**：

- [x] **明示豁免**（董事会 2026-09-04 裁定）：在路线 B 有效期内，
      DIR-07 / M-DEC-02 **暂停适用**；认证链重启时（见 §4 重启条件）**恢复适用**。
- [ ] ~~不豁免~~

**豁免边界（不得外推）：**

| 豁免了什么 | 未豁免什么 |
|---|---|
| 「代码改造须先有 R1 架构批准」这一**顺序要求** | **任何技术门禁**——E1 FAIL、E2/E3/E4 BLOCKED、生产启用 BLOCKED、`REL-BLOCK-01` 均不受影响 |
| 已执行的 9 批改造无需补上层依据，也无需回退 | **改造质量要求**——每批仍须全量测试通过、留行为级回归、记录 DEVELOPMENT_LOG |
| —— | **DIR-01~06 其余六项方向要求**，继续适用 |

> 豁免的是**流程顺序**，不是**质量标准**，更不是**安全门禁**。

> **不作裁定的后果**：将来任何人对照指令核查，会发现一个无解释的违反项，
> 且无法判断它是「经批准的偏离」还是「未被发现的失控」。

### 裁定一：M-06 保持部分完成，不再推进

`execute_write_tool_stub` 明写「不触发外部 IO」，因此**「批准即生效」不成立**：
审批链路跑得通，但批准完什么也没真发生。前端 `agent-v2.ts:193` 硬编码
`mode:'message'` 使 command 模式永不触发——两个断点互相依赖，**先修前端会让
command 模式走到一个空 stub，比现状更差（现状至少诚实）**。

MVP 阶段 agent 写工具本就不应真执行，现状是安全的保守默认。

**由此产生的对外表述约束（追加至 §8）：**

- **不得**称「审批闭环已建立」「批准即生效」「agent 具备写入能力」
- **可以**称「已建立审批请求—决策—记录链路；批准后的实际写入执行为受控占位，
  agent 当前不对系统产生写副作用」

### 裁定二：CI 暂不核查

分支已按 §9-3 推送，但主审无法读取 GitHub Actions 结果（本机无 `gh` CLI，
需交互式 `gh auth login`）。**「CI 可信」这一前提仍无证据**——
`M-10` 修复后 CI 从未在 GitHub 上真跑过。

**对外表述约束：不得声称「CI 验证通过」。** 本地全量绿 ≠ CI 绿。
