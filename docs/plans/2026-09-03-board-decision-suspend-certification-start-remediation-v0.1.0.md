# 董事会裁定：暂停审计认证链，转入 P0 改造

- 版本：0.1.0
- 日期：2026-09-03
- 裁定人：董事会（用户）
- 裁定原话：**「B」**（对「路线 A 走完认证链 / 路线 B 接受现有结论转去修问题」的选择）
- 生效范围：审计治理流程与改造启动顺序。**不改变任何已登记的技术结论。**

## 1. 裁定内容

董事会选择**路线 B**：

1. **接受现有 26 项问题清单**（P0 8、P1 11、P2 7）作为改造输入；
2. **明示接受其验证等级为 E1**（静态代码、配置、数据库只读观察）；
3. **暂停 A0–A6 与 R0 的认证链**，不再以「阶段正式通过」为改造前置条件；
4. **改造工作即刻开始**，按 P0 优先级推进。

## 2. 为什么这不是跳过

审计要回答的问题是「系统哪里有问题」。**这个问题已经答完了**：
26 项问题各有编号、根因、代码位置、证据等级与最小后续验证方法，
经八轮异源复核、累计推翻主审 24 条实质结论后固化。

认证链剩余部分（AG-01~AG-05、A1–A6 逐阶段再批准、R0 补证）**证明的是审计过程合规**，
不是系统状态。**这些技术结论不因缺少合格证而失真。**

墙钟：2026-09-25 到期，裁定日剩 22 天。经评估，认证链无法在期限内走完
（仅 R0 的 D-01/D-02/D-05/D-06/D-07 五域仍停在第一轮首屏发现）。
在「拿到合格证」与「修好问题」之间，董事会选择后者。

## 3. 明确承担的代价

| 代价 | 说明 |
|---|---|
| AG-01～AG-05 永久停在未闭合 | 批准链、M-AUD-06、P0 主备通道、阶段指纹、当前漂移 |
| A0–A6 永远不是「正式通过」 | 七份报告的状态维持 `RETURN FOR REVISION` / `IN REVIEW` |
| R0 无合格主参考 | 6 个软件候选因 G2/G5 不完整全部 NOT_ELIGIBLE，该结论不再补证 |
| R1 不再作为独立阶段 | 目标架构设计并入改造批次，不单独设门禁 |
| **对外使用受限** | 若本材料用于投标、尽调或合规场景，**此缺口会被对方看见**，且不得表述为「审计已通过」 |

**E2/E3/E4 与生产启用继续 BLOCKED，`REL-BLOCK-01` 未清零。**
本裁定**不解除任何技术门禁**，只解除「改造必须等认证链走完」这一流程前置。

## 4. 重启条件

出现下列任一情形时，认证链应当重启，且从 AG-02 开始：

1. 本材料需要对外用于投标、尽调、认证或合规审查；
2. 出现真机（E3）或课堂（E4）交付需求；
3. 董事会认为改造结论的可信度需要独立背书。

重启时 A0–A6 的现有材料仍然有效，作为重开的起点而非重做的对象。

按「改动面小、可测试、能立即验证」排序，先建立可复用的模式再批量推广：

### 7.2 DIR-07 / M-DEC-02 的豁免

董事会指令 DIR-07 要求「未来只能按架构 → 模块 → 文件 → 代码的顺序制定和执行改造」，
M-DEC-02 的返工阈值为「任一代码任务缺少上层批准依据即不得进入实施」。

路线 B 下已执行的 9 批代码改造**无上层 R1 目标架构批准依据**，属逆序执行。
这是路线 B 裁定的直接后果，非擅自越界，但**指令层面需明示豁免**：

- [ ] **明示豁免**：在路线 B 有效期内，DIR-07 / M-DEC-02 暂停适用；
      认证链重启时（见 §4 重启条件）恢复适用。
- [ ] **不豁免**：则已执行的 9 批改造须补上层批准依据，或回退。

> **不作裁定的后果**：将来任何人对照指令核查，会发现一个无解释的违反项，
> 且无法判断它是「经批准的偏离」还是「未被发现的失控」。
