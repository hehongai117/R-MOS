2. 形成“默认拒绝 + 显式公开路由白名单 + 对象归属 + 拒绝审计”的 ADR。
3. 形成“任务/执行/快照不可变机器人绑定 + 按机器人隔离适配器”的 ADR，并写迁移与回滚方案。

5. 形成 AI 策略、禁止自批、审批执行门禁、审计失败阻断和可靠落库方案的 ADR。
6. 形成单进程/多进程共享状态、生产存储、迁移、就绪和恢复的 ADR。
7. 写 Phase 3 和 Phase 4 的分批 TDD 执行计划，每批只解决一类风险。

**进入条件**：新窗口已从最终交接提交建立独立工作区；用户确认采用本文件的 Phase 2 定义。

**完成条件**：29 项发现全部映射到可复现门禁；P0/P1 不再有未决设计歧义；涉及架构、数据结构、权限、审批、审计和生产边界的决定已单独向用户汇报并获得确认。

### Phase 3：AUTH、CTRL、RT 基础修复

**目标**：以失败测试先行，修复身份边界、对象隔离、机器人控制归属和实时通道隔离。

**范围**：`AUTH-101` 至 `AUTH-105`、`CTRL-101` 至 `CTRL-105`、`RT-101` 至 `RT-104`。

**进入条件**：Phase 2 的 ADR、迁移、回滚和 TDD 计划完成；用户明确批准 Phase 3 的权限、数据结构和控制边界实现；从已确认的 Phase 2 最终提交建立独立工作区。

**建议分批**：

1. 默认认证和公开白名单门禁。
2. 服务端身份上下文、角色、学校和对象归属；拒绝也写真实资源编号。
3. 私有/已发布资产边界与登录失败限制。
4. 机器人不可变绑定、按机器人适配器和现场检查默认阻断。
5. 统一取消/停止流程、幂等和并发提交复现及修复。
6. WebSocket 认证、机器人/频道订阅隔离、心跳、时间格式和前端切换。

**强制门禁**：

- `AUTH-GATE`：匿名、伪造身份头、跨学生、跨教师、跨学校访问允许数为 0；公开路由必须显式登记。
- `CTRL-GATE`：控制写入必须有身份、角色、机器人归属、审批和审计；未知设备/工具状态默认阻断；存在可验证停止路径。
- `RT-GATE`：匿名连接拒绝；每个用户只能收到授权机器人和频道；心跳、重连、切换和时间格式有自动测试。
