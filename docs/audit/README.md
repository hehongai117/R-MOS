## A1 当前结论

A1 用双源枚举回答「项目实际有什么」：后端 181 条 HTTP 路由与 2 条 WebSocket 端点在静态 AST 与运行时注册表两侧逐条对应，差集为 0；65 张业务表在源码、ORM metadata 和数据库三侧一致，数据库多出的 `alembic_version` 是 Alembic 自带；38 个迁移单一 head 且与数据库版本一致。

同时登记了三类必须进入后续阶段的事实：**33 条路由在本批口径下没有任何消费者或测试引用**（assessments 域独占 11 条）；**AI 审批的批准/驳回接口唯一页面级调用点是不可达的 `ApprovalQueuePage`**；**65 张业务表中 28 张为空**。

本批没有执行任何测试，只做收集与列举，因此全部验证等级上限为 E1，`REL-BLOCK-01` 未受影响，E2 至 E4 与生产启用继续 BLOCKED。
Codex 两轮异源复核（20 条断言）已结束，抓出的 2 条 MISMATCH——前端零引用判定漏算再导出、空表数误用统计估算值——均由主审逐条复验后采纳并修正。A1 已满足全部退出门禁，并于 2026-08-27 获董事会以「提交，继续」整体确认（未逐节点评），A1 提交为 `67a4ce30`，现进入 A2。

## A2 当前结论

A2 用两条硬证据判定每条流程：**写操作在前端有没有入口**，以及**数据库里有没有数据**。结论是系统只有 4 条流程真正闭合（注册入校、登录会话、机器人接入建模、评分与技能画像），另有 7 条 PARTIAL、3 条 SEEDED_ONLY、2 条 BROKEN、2 条 MISSING。

三处结构性问题：**94 条写操作路由只有 51 条能从前端发起**，教学建班/建课/加入/布置作业与训练会话生命周期全部没有 UI 入口；**机器人控制与异常停止在系统层面不存在**（适配器契约只有连接、读取与故障注入）；**前端有 15 条调用指向后端不存在的端点**，其中用户设置页的改密码与改资料对所有用户必然失败。

数据时间轴显示教学与训练闭环的全部数据停在 2026-05-14，三个半月无新增；仍在演进的是 SOP／任务链路。

Codex 异源复核 13 条断言，抓出 3 条 MISMATCH（数据归因错、审批消费方向说反、把前端悬空调用当成已存在实现），全部复验成立并已采纳；其中第三条反向查出 15 条悬空调用，比原结论更严重。本批未执行测试，验证等级上限 E1。
