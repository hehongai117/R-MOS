## 5.8 四种 E2 状态的定义与判定规则

本报告全篇使用四个标记，含义**不可互换**：

| 标记 | 含义 | 判定规则 |
|---|---|---|
| `E2_COLLECTED` | 本轮已取得新鲜、合格的受控 E2 证据 | 须绑定提交、环境、命令、原始输出与退出结果 |
| `E2_HISTORICAL` | 有证据，但对应的是**旧提交或旧环境** | 只说明当时那次运行，**不代表当前提交**；不得作为当前 PASS |
| `E2_NOT_COLLECTED` | **本轮没有采集**，但不存在已知硬阻断 | 条件具备时可直接按受控方案补采 |
| `E2_BLOCKED` | **存在已知前置障碍**，采集无法进行或即使进行也形不成合格证据 | 必须先清除障碍才能采集 |

**`NOT_COLLECTED` 与 `BLOCKED` 的分界线**——只看一个问题：

> **障碍是否已经确认存在？**

- 「**没安排、没排上、还没做**」→ `E2_NOT_COLLECTED`
- 「**能力本身不存在**（如无备份脚本）、**没有等价环境**、**授权未获批**、
  **安全门禁禁止**」→ `E2_BLOCKED`

> ⚠️ **易混点：「尚未批准」属于 `E2_BLOCKED`，不属于 `NOT_COLLECTED`。**
> 未获授权是一个**已确认的前置障碍**，不是「还没安排」。
> 同一事项不得同时归入两类。

**两者的共同点**：都**不**表示能力已失败。除非另有直接失败证据，
二者只说明「尚无合格证据」，不得解读为「已证伪」。

## 5.9 本报告全部结论的证据边界（**适用于每一条 E2 标记**）

无论后续补齐何种运行证据，下列边界始终成立，不得省略：

| 边界 | 含义 |
|---|---|
| **只证明对应提交与环境** | 一次运行证据只说明「**该提交、该环境、该次执行**」的结果，不代表其他提交或其他环境 |
| **不能倒改历史基线** | 当前 HEAD 取得的证据**不得**用于改写 `B-ASIS` 时点的历史结论；历史缺陷不因当前已修复而消失 |
| **不能外推到未取证的层级** | 受控 E2 证据**不能**推出预生产、生产、真机（E3）或课堂（E4）通过；三者需各自取证 |
| **不能以配置替代运行** | 工作流文件、脚本、文档声明的存在，都不构成「实际成功运行过」的证据 |
| **不能以历史数字替代当前** | 旧提交的测试通过数不代表当前提交；须重新绑定提交与环境 |

> **这是本审计最核心的一条纪律。** `E1 FAIL`、`E2/E3/E4 BLOCKED`、
> `REL-BLOCK-01` 未清零，全部由该边界推出；一旦允许外推，这些门禁将失去意义。
