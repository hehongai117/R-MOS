### 1.1 系统的真实画像（一句话版本）

**这是一个骨架健康、写路径薄弱、运行能力空白的系统。**

- **骨架健康**：后端分层干净（跨层依赖单向，三个反向方向边数均为 0，全仓仅 1 组循环依赖）；
  认证网关默认拒绝且白名单仅 7 条；测试不是假绿（2468 条断言，中位数 3）；
  CI 有真 PostgreSQL + `alembic upgrade head` + `alembic check`；
  对象归属边界测试成体系（跨学生／跨校读→404、提权防护）。
- **写路径薄弱**：94 条写操作只有 10 条有对象归属校验，且全在 `robots`／`onboarding`；
  46 条写端点在代码层面拿不到调用者身份；教学与训练的建立类写入口在前端完全缺失；
  写路径既无授权也无授权测试。
- **运行能力空白**：无监控、无备份、无恢复演练、无依赖漏洞扫描、无后端静态检查；
  两项 CI 配置缺陷（`DEBUG` 被 YAML 重复键吃掉、`/health` 从不返回 503）使
  "CI 在跑且能发现问题"这一假设本身需要重新验证。

### 1.2 八个 P0

> 严重度采纳异源复核的分级规则：**P0 = 可能造成越权、身份冒用、消息泄露、机器人安全失控，
> 或直接阻断生产恢复与真机交付**。主审初稿定 5 个 P0，复核方定 8 个；逐条比对后**采纳复核方分级**，
> 差异说明见 §9.2。

| Master_ID | 一句话 | 为什么是 P0 |
|---|---|---|
| **M-01** | 94 条写操作仅 10 条有对象归属校验；46 条写端点拿不到调用者身份，其中 27 条路径直接带对象 ID | 任意登录用户可给任意作业打分、删任意 SOP、批准任意维保草稿 |
| **M-02** | `force-submit` 校验的是**请求体自带的** `teacher_id`，不是认证身份，且该编号被写入记录作为操作人 | 身份冒用，且留下伪造的操作人痕迹；静态扫描会给它打勾 |
| **M-03** | WebSocket 零认证、`robot_id` 不用于过滤、`send_to_user` 实为全量广播 | 匿名可连接收全量遥测；"定向"消息跨用户泄露且调用方无从察觉 |
| **M-05** | `adapter` 域 5 条端点**依赖列表为空**，含 `POST /adapter/inject-fault` | 任意登录用户可改变机器人故障状态，无授权无审计 |
| **M-06** | 审批两套实现：一套前端函数零页面调用，另一套写操作 UI 不可达；实际使用的一套用**进程内内存队列不落库** | AI 高风险动作缺少可靠且可追溯的人工闸门 |
| **M-07** | 适配器契约无运动控制与急停；急停仅在 Mock 内由中文关键词触发，无端点 | **直接阻断 E3 真机资格与交付** |
| **M-13** | **`auditor` 拥有 `approvals:grant`/`reject`**（职责分离冲突）；角色三处并存且 RBAC 表运行期不可维护 | 权限冲突已存在于配置中，一旦创建 auditor 账号立即生效；且无法在线纠正 |
| **M-18a** | **无备份脚本、无恢复演练、无真实回滚演练**（回滚计划文档自述） | **直接阻断生产启用与故障恢复** |
