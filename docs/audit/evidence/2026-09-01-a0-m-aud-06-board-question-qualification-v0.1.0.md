## 2. 董事会冻结题目原文

### A0-Q01 [BOARD-NEW｜FROZEN]

同一句“给学生布置一个机器人维保任务”，分别用下面两种请求送进统一助手入口：请求 A 使用 `mode=auto`，只提供 `intent=dispatch` 与 `input_text`；请求 B 使用 `mode=auto`，只提供 `message` 与 `idempotency_key`。请从请求进入到响应返回，逐段说明两者最终进入哪条处理路径、各自要求什么权限、会不会形成命令、工具调用或审批记录、是否经过策略判断与模块分派、重复使用同一个幂等键时会发生什么，以及调用方最终能从 `mode_used`、`status`、`from_cache`、`approval_id` 看出哪些差异。

区分度说明：这道题要求把自动分流、权限、持久化记录、策略判断和返回结构连成一条链；只知道“系统有助手和审批”无法作答。

### A0-Q02 [BOARD-NEW｜FROZEN]

从系统真实产生一条待审批记录后，管理员在审批队列里依次执行“批准一次”“再次批准同一条记录”，然后分别切换到“待审批”“已批准”“已拒绝”三个视图。请说明每一步涉及的前端筛选值、后端保存值、命令状态、工具调用状态、是否再次执行，以及应当出现的审计事件；最后判断页面提示“已批准”本身是否足以证明这条命令已完成。

区分度说明：这道题必须同时追踪页面、接口和审批后的运行状态，能识别显示口径与真实状态是否一致；背审批流程概念答不出来。

### A0-Q03 [BOARD-NEW｜FROZEN｜可证伪性题]

待检结论是：“R-MOS 的每一条有副作用命令都会先完成风险分级，只有满足对应审批级别后才发生真实写入，并且同一个 `trace_id` 能完整回放这条链。”请设计一次最小验证，并明确写出：出现什么具体证据即可推翻这个结论。证据必须覆盖请求、命令、工具调用、审批、审计回放和被写目标的实际变化，不能只凭接口返回的 `success` 或页面提示下结论。

区分度说明：这道题要求考生知道真正的执行入口、记录之间如何关联，以及“返回成功”“审批通过”“真实写入”“可回放”不是同一件事。

### A0-Q04 [BOARD-NEW｜FROZEN]

一个已存在的知识引用属于用户甲，用户乙读取它；另一个引用编号在数据库中根本不存在。两次请求对调用者看起来都可能像“资源不存在”。请比较这两种情况在外部响应、内部拒绝记录、真实 `resource_id`、拒绝原因和后续按 `trace_id` 回放时的差别，并说明为什么不能仅根据 HTTP 状态判断二者相同。

区分度说明：这道题只有追过对象级读取、异常处理和审计写入顺序的人才能回答，通用的“越权返回 404”常识不够。

### A0-Q05 [BOARD-NEW｜FROZEN]

系统里有两条都叫“证据完成”的路径：一条先调用步骤证据收集接口，再查询该步骤能否继续；另一条创建并封存证据包。请用同一份示例证据贯穿两条路径，比较它们如何判断“齐全”、如何校验引用或类型、数据保存在哪里、进程重启后还剩什么、完整性如何证明，以及怎样构造一个“一条路径显示完成、另一条路径仍不能证明完成”的场景。

区分度说明：这道题要求理解两套证据机制的真实数据结构和生命周期，不能靠看到相似命名就把它们当成同一能力。

### A0-Q06 [BOARD-NEW｜FROZEN｜可证伪性题]

待检结论是：“准备清单或验收清单在页面上显示完成，且 SOP 进入完成状态，就必然意味着服务端已经保存了全部清单证据；服务端也不可能在步骤证据缺失时触发任务报告。”请设计一个包含网络中断或单次请求失败的最小实验，并明确指出：哪些前端状态、网络请求顺序、服务端步骤记录和任务状态一旦同时出现，就足以推翻该结论。

区分度说明：这道题必须看懂本地裁决、异步同步和任务完成触发之间的先后关系；只会操作页面的人很容易把界面完成误当成服务端闭环。

### A0-Q07 [BOARD-NEW｜FROZEN]

“共享机器人”和“已发布机器人”看起来都像是在让别人可用，实际不是一回事。设教师甲创建机器人，教师乙尝试引用，乙名下学生再进入选机页面。请分别推演以下顺序下三个人能看到什么、能做什么，以及绑定关系如何变化：甲先设为共享但仍是草稿；甲随后发布；乙引用成功；甲最后改回私有。回答必须覆盖共享库、教师机器人列表、学生可用列表、机器人详情和学生端历史选择恢复，不能只描述两个状态字段的字面含义。

区分度说明：这道题要求跨越可见性、发布状态、教师绑定、学生归属和前端选机规则，只有真正看过多机器人链路才答得完整。

### A0-Q08 [BOARD-NEW｜FROZEN]

同一个机器人资产地址，在本地文件存储和 S3 兼容存储下都可能最终让浏览器拿到同一份 GLB。请说明两种后端在“先确认文件存在、向浏览器下发、释放资源、拒绝目录穿越、供分析流水线取得本地文件或目录”这五个环节的实际差别，并给出仅观察 HTTP 交互与分析期间临时文件生命周期时，如何判断当前走的是哪一种实现。

区分度说明：这道题考查的是 R-MOS 自己的存储边界和调用顺序，不是泛泛比较“本地磁盘与对象存储”。

### A0-Q09 [BOARD-NEW｜FROZEN｜可证伪性题]

待检结论是：“机器人设为私有后，未登录者既看不到机器人详情，也不可能直接取得它的 3D 模型或清单文件。”请给出最少的一组请求来验证这个结论，并明确说明：什么响应组合足以推翻它。验证必须区分机器人详情、资产元数据列表和具体资产内容三个入口，同时说明每个入口实际检查了什么身份或状态，不能从前端是否展示链接反推安全性。

区分度说明：这道题要求逐个检查真实接口边界，能够识别“目录不可见”和“文件不可取”是否被同一套规则保护。

### A0-Q10 [BOARD-NEW｜FROZEN]

同一个 SOP 步骤因相同前置条件或完成条件失败，分别发生在教学、考试和维保三种模式。请逐一说明执行器状态、能否重试、是否给提示、是否进入致命失败、是否要求结算、阻断窗口是否出现，以及回调会如何传播到页面；随后把该步骤设为不可逆，并在执行中或完成后尝试回到上一步，说明这会怎样改变用户可见结果。不得只引用模式名称或界面文案。

区分度说明：这道题必须追踪失败裁决、模式分支、执行器状态和页面反馈，能区分“同一次失败”在三种运行语义下为何不是同一结果。

最终结论：10 道题已按 `BOARD-NEW｜FROZEN` 冻结，可直接用于 M-AUD-06 独立考核。
