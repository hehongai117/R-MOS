### A0-Q01

三个时间边界分别回答不同问题：

### A0-Q04

这两半必须分开，因为“根因存在”和“精确数量是多少”是两种不同强度的结论：

- “代表性 FACT”表示已经能在具体写入口中直接确认：调用者身份、对象归属或两者的绑定存在缺口。因此风险不能因为旧统计失效而被删除。
- “精确计数 SUSPENDED”表示旧的全量枚举方法、分母或分类口径不能独立复现，所以不能继续声称整个系统恰好有多少写入口、多少已保护、多少未保护，也不能据此计算覆盖率。

- 无法区分已修、暂时保护、数据结构阻断和真正完成，容易把“入口已有守卫”误报为根因已经消失。
- 会把测试设计成验证旧总数，而不是逐入口验证正确的人、正确的对象、正确的职责分离和拒绝结果。

因此应保留已确认的根因，同时重新建立可复现、绑定当前提交且能区分授权语义的分母。

### A0-Q05

两者虽然都带“机器人”三个字，但审计对象根本不同：

- 机器人资产管理处理的是数字对象：机器人型号记录、文件上传、三维模型、分析任务、发布状态、共享范围、教师绑定、资产下载以及这些数据的增删改查和访问权限。
- 机器人运动控制处理的是物理动作：运动命令、目标设备绑定、命令状态、动作确认、速度和范围限制、停止、急停、断网处置、超时、重试、防重复执行、审批、审计以及真实安全联锁。
- 当前机器人适配器主要提供连接、状态读取、传感器读取和教学用故障注入，没有产品级运动命令和急停约定。
- 模拟器中由关键词触发的内部“停机”行为，不等于对外可调用、可审计并经过真机验证的急停能力。

因此，即使资产页面、资产接口和全部相关自动测试通过，也只能证明对应资产功能在测试覆盖范围内成立，不能证明：

- 运动控制接口存在；
- 命令会发送到正确的真实机器人；
- 未经授权或审批的动作会被阻止；
- 重复请求不会重复动作；
- 断网、超时和重连安全；
- 停止与急停可靠；
- 物理联锁有效；
- 真机验收已经完成。

运动控制和急停必须先有明确安全约定，再分别取得受控运行证据和 E3 真机证据。资产功能通过不能替代这些证据。

### A0-Q06

如果要推翻 A4 对 `B-ASIS` 的历史结论，必须出现绑定 `B-ASIS` 的可复现证据，证明真实用户入口当时已经在动作发生前进入审批闸门。当前代码后来接线，只能改变当前状态，不能改写历史。

如果要证明当前代码已经形成完整审批执行链，至少需要一条受控的端到端证据链同时证明：

- 真实用户从实际使用的入口发起高风险动作，而不是直接调用一个孤立的审批接口。
- 系统先判断该动作需要审批，并在任何业务动作、外部调用或设备动作发生前停止执行。
- 待审批记录已经持久保存，并与调用者、动作、目标对象、参数、命令、执行记录和同一个追踪编号绑定。
- 服务重启后待审批状态仍存在，不能因为进程内数据丢失而绕过审批。
- 只有具备相应职责、且满足职责分离要求的人可以批准；无权批准、自我批准和伪造批准者都必须被拒绝并留下记录。

- 执行只发生一次，成功或失败都形成完整的最终状态和审计记录。

批准、拒绝和重复操作还要分别证明：

- 批准：第一次合法批准才触发动作；审批记录、动作结果和审计记录使用同一追踪编号。
- 拒绝：拒绝后动作执行次数为零，即使刷新、重试、重启或再次请求也不能执行。
- 重复操作：重复批准不能重复执行动作，也不能重复写入“执行成功”；重复拒绝不能产生新动作；批准后再拒绝或拒绝后再批准必须按明确规则拒绝冲突变化。
- 并发提交两个相同决定时，也只能有一个状态变化和最多一次动作。
- 所有被拒绝、重复和冲突操作都要有真实目标编号的审计记录。

当前改造记录只能证明一部分进展：执行前拦截和 message 模式创建持久审批记录已经补上，但前端仍固定走 message 模式，command 模式没有真实消费者；批准后执行的仍是无真实副作用的占位动作。因此现有证据最多支持“部分修复、仍需复验”，还不能完全推翻“审批没有完整进入真实执行路径”的结论。

### A0-Q07

两者共同点都是“当前没有合格的新鲜 E2 证据”，但原因不同：

- `E2_NOT_COLLECTED`：采集条件原则上具备，也没有已确认的硬障碍，只是本轮尚未安排或执行。按批准的受控方案可以直接补采。
- `E2_BLOCKED`：已经确认存在前置障碍。可能是能力本身不存在、没有等价环境、没有备份或回滚工具、没有取得授权，或者安全门禁明确禁止执行。必须先清除障碍，直接采集也无法形成合格证据。

A5 报告可能获批，是因为 A5 审查的是“现有证据到底能证明什么”。如果报告做到以下事项，它可以作为一份诚实、完整的审计报告获得批准：

- 没有用配置文件、测试数量或文档声明代替实际运行。

但报告获批只表示“报告准确描述了证据边界”，不表示被审能力已经通过。生产能力仍不能判定通过，因为备份、恢复、回滚、断网、预生产、真机和课堂等证据仍然缺失或受阻；E1仍失败，E3/E4仍受阻，`REL-BLOCK-01`仍然生效。A6和R1只能把相关维度保留为未知、阻断或后续调查项，不能据此作出绑定性的生产承诺。

1. 固定当前工作区、最终提交、环境指纹和 `B-ASIS` 之后的全部漂移；逐项关联原批准、目标发现和当前验证结果。

2. 完成 A0 尚未闭合的门禁：

   - 分别完成非破坏性送达测试，并保存接收人、时间、发送记录和真实回执；
   - 完成 A0 的十题冻结、原始回答、非主审逐题评分、10/10结果和角色独立性记录；

   - 固定最终提交和零越界变化证据。

3. 只有上述条件闭合后，才能取得准确口令 `确认 Audit A0`。重开口令、材料完成、机械检查通过或十题回答完成，都不能代替这一批准。

4. A0批准后，按 A1→A2→A3→A4→A5→A6的顺序逐阶段重开、重验和批准，不能跳级：

   - A2重新核对真实用户流程、断点和孤立功能；
   - A3重新核对模块、数据所有者、共享状态和重复实现；

5. 上游阶段全部重新批准后，重新生成 A6：
