# A0 M-AUD-06 冻结评分标准

- 冻结日期：2026-09-04
- **本文件不得提供给答题者**
- 总规则：每题只记「对」或「错」，不给部分分。满分要点须全部出现；
  同义表达可接受，遗漏任一点、混淆事实边界或加入相反结论，整题判错。

## A0-Q01 [SETTER-DRAFTED]

满分要点：

- `B-REF` 是 Phase 3 应用变化开始前的参照点，用来回答干预前是什么状态。
- `B-ASIS` 是本轮审计固定的历史现状，A4 的历史发现必须按该状态判断。
- `B-REF` 到 `B-ASIS` 的变化应进入干预集，逐项关联原批准和验证状态。
- 当前代码属于后续状态；修复只能通过新基线和复验说明“现在怎样”，不能倒改 `B-ASIS` 的事实，也不能自动关闭历史发现。

常见错误答案：

- “当前代码最准确，所以历史发现应删除。”
- 把 `B-ASIS` 说成当前工作树或最新提交。
- 认为代码被删除就等于当时的批准、验证和安全门禁全部补齐。

判定规则：四项满分要点全部答到才判对，否则判错。

## A0-Q02 [BOARD-REPLACED]

满分要点：

- 产品问题是**被审系统**的缺陷；AG 是**审计过程本身**未闭合的治理项，两者的责任方与修复动作完全不同。
- AG 未闭合会使全部阶段结论的**正式地位**失效（报告只能算预编材料），与「某个功能有 bug」不是同一量级。
- 混算会稀释：31 个里 8 个 P0 看起来「大部分问题不严重」，而实际上 AG 是**前置阻断**，不闭合则其余 26 项的结论都不能作为正式依据。
- 混算还会让治理项被当作可排期的技术任务处理，而它们需要的是人工批准与送达证据，不是写代码。

常见错误答案：

- 「都是问题，合起来排序更清楚。」
- 只说「分类不同」，不解释后果。
- 把 AG 说成优先级更低的问题。

判定规则：必须答出①两类对象不同（系统缺陷 vs 审计过程）②AG 是前置阻断、影响其余结论的正式地位 ③混算会稀释或误导优先级；缺一项即判错。

## A0-Q03 [SETTER-DRAFTED]

满分要点：

- HTTP 必须保存同一提交、同一环境下的静态清单和运行时路由或 OpenAPI 原始输出。
- HTTP 对差键必须包含最终完整路径、请求方法和所有挂载前缀，并逐项解释差异。
- WebSocket 必须使用能观察真实注册或可达性的异源证据，并人工处理动态拼接的地址；重复做静态字符串搜索不算异源。
- 证据必须带可复现命令、环境、时间和原始结果；只有解释后差集确实为零，才能推翻原判断。

常见错误答案：

- 只重跑原脚本。
- 只比较函数名、局部路径或装饰器文本。
- 用前端字符串未命中证明 WebSocket 无消费者。
- 没有保存原始输出，只给汇总数字。

判定规则：HTTP 和 WebSocket 两部分都完整答对才判对；任何一部分缺失即判错。

## A0-Q04 [BOARD-REPLACED]

满分要点：

- **根因保留**：写入口未接收调用者身份或未做归属判定，这一事实有代表性代码实例支撑，属 FACT。
- **分母暂停**：「94 条 / 10 条」的精确计数不可复现（口径与脚本未留证），故标 SUSPENDED，不得引用。
- 二者分开，是为了「问题成立」与「问题有多大」不相互绑架：分母不可复现不等于问题不存在，问题存在也不等于那个数字可信。
- 只保留一个总数的误导在于：该表述隐含「这是代码疏漏，补守卫即可」，而实际上**其中一部分是数据模型根本不记录归属**（相关表无创建者/拥有者字段），补守卫也无法实施对象级隔离。两类的修复路径完全不同——一类改代码，一类要改 schema 并处置历史数据。

常见错误答案：

- 「暂停计数就是这个问题不成立。」
- 只说「数字不准」，不指出两类问题修复路径不同。
- 认为补上守卫即可关闭 M-01。

判定规则：必须答出①根因与分母分开的理由 ②「一个总数」会掩盖「代码疏漏 vs 数据模型缺归属字段」这两类；缺一项即判错。

## A0-Q05 [SETTER-DRAFTED]

满分要点：

- 资产管理处理的是机器人型号、实例、元数据、文件或可见性等管理对象。
- 运动控制和急停处理的是实际动作命令、状态变化、停止能力及故障情况下的安全行为。
- 控制链还需要身份与对象权限、审批、审计、命令状态以及现场安全联锁。
- 资产链和自动测试最多证明相应静态实现或自动证据，不能替代产品级控制契约和真实机器人安全证据，因此不能据此认定运动控制或急停可用。

常见错误答案：

- “机器人已经能在系统中显示，所以系统可以控制它。”
- 把删除、编辑机器人记录称为急停能力。
- 用模拟适配器或单元测试代替真实机器人安全验证。

判定规则：必须同时说清两个对象的差别、控制链额外要求和不能互相替代的结论；缺一项即判错。

## A0-Q06 [SETTER-DRAFTED]

满分要点：

- 真实用户动作必须在产生副作用前进入同一套持久化审批链，并关联调用者、对象、命令、工具调用和同一追踪标识。
- 等待审批期间不得发生目标动作。
- 批准后只能恢复并执行原动作一次；重复批准必须保持幂等，不能再次产生副作用。
- 拒绝后必须阻止动作并留下相符的终态和审计记录。
- 所有实际执行分支都必须受这条链约束；孤立或无人消费的内存审批队列不能被当作证明。

常见错误答案：

- “数据库里有审批表，所以审批闭环成立。”
- “界面显示等待审批”但动作实际上已经发生。
- 只验证批准，不验证拒绝和重复批准。
- 只证明一条执行分支，忽略其他真实入口。

判定规则：五项全部满足才判对；只证明审批设施存在或只覆盖单一路径均判错。

## A0-Q07 [SETTER-DRAFTED]

满分要点：

- `E2_NOT_COLLECTED` 表示相应运行证据尚未采集，并不单独说明能力好坏。
- `E2_BLOCKED` 表示采集受到批准、环境等价性、安全条件或能力缺失等阻碍，当前不能合法或可信地完成。
- 两者都不等于运行能力通过，也不能无证据直接判定具体运行结果失败。
- A5 可以因为如实、完整地报告证据边界而获得审计批准，但相关能力在 A6、R1 和生产判断中仍须保持未知或阻断；生产门禁不会随文档批准解除。

常见错误答案：

- 把两种状态当成完全相同。
- 把 `NOT_COLLECTED` 直接解释为测试失败。
- 认为 A5 报告获批就等于恢复、回滚、真机和生产全部通过。

判定规则：必须准确区分两种状态，并说明“报告可获批”和“能力可通过”是两个门禁；缺一项即判错。

## A0-Q08 [BOARD-REPLACED]

满分要点：

- **性质不同**：数错行是**算术/一致性错误**，可由机械比对发现；属性写反是**事实错误**，报告内部完全自洽，机械检查无从察觉。
- **属性写反更危险**：它会直接改变处置方向——若据此认为「落库的那套不可用」，就会去重建一套已经存在且实现规范的设施，而真正的断点（闸门不在执行路径上）反而被掩盖。
- 数错行影响的是数字可信度，读者仍可自行重数；写反影响的是结论本身，读者无从察觉。
- **机械检查的边界**：新增脚本能防住数错行（比对台账实际行数与声明值），**防不住属性写反**——因为脚本只能校验一致性，不能校验与代码的对应关系。该类错误只能靠异源复核回到一手来源核实。

常见错误答案：

- 「都是错误，一样严重。」
- 认为机械检查能防住两个。
- 只描述错误内容，不区分「可被机械发现」与「只能靠异源复核发现」。

判定规则：必须答出①两类错误的性质区别 ②属性写反更危险及其理由 ③机械检查只能防住前者；缺一项即判错。
