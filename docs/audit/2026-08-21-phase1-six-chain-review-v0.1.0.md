## 1. 证据和严重级别

- **事实**：可由当前代码、配置、测试输出或可复现命令直接确认。
- **推断**：代码形态显示存在风险，但尚缺少专门测试或运行证据。
- **未知**：当前材料不能作出结论，必须补充环境、真机或专项演练。
- **P0**：未修复前不得通过 E1，存在直接越权、绕过关键安全门禁或不可接受的数据/控制暴露。
- **P1**：上线或高风险使用前必须修复，当前设计不能满足既定安全、隔离或恢复要求。
- **P2**：需要进入后续修复计划，影响完整性、隐私、稳定性或测试可信度。
- **P3**：低风险质量问题或改进建议。

## 4. 第一批发现：身份、对象归属与控制

### AUTH-101｜关键任务和教学接口可绕过令牌认证

- 链路：身份、角色与对象归属
- 类型：事实
- 严重级别：P0
- 证据：路由清单脚本递归检查 `get_current_actor` 依赖，当前 `/api/v1` 下有 109 个读写路由未声明该依赖。这个数字包含明确公开接口，因此不能把 109 个全部称为漏洞；但代表性高影响非公开入口已由代码确认。
- 代码证据：
  - `app/api/v1/endpoints/tasks.py:31-110,142-262`：创建、开始、执行步骤、暂停、恢复、详情、报告和事件均不要求当前用户；只有列表入口在 `113-139` 使用认证身份。
  - `app/api/v1/endpoints/student_tasks.py:39-67`：调用方可直接传入任意 `student_id` 读取任务执行记录。
  - `app/api/v1/endpoints/teaching_roster.py:61-84`：班级列表和创建入口无认证；同文件大量课程、作业、尝试入口也采用相同模式。
  - `app/api/v1/endpoints/training.py:290-333`：强制提交直接信任请求体中的 `teacher_id`，可用被冒用的教师编号通过班级范围检查并写入审计。
- 影响：未登录调用者可读取他人任务和报告，或改变任务、课堂、训练状态；违反 G1 和 G2。
- 最小修复方向：建立明确的公开路由白名单，其余 `/api/v1` 路由默认要求服务端令牌身份；所有对象读写必须用认证身份做学生、教师、学校和资源归属校验，禁止从请求体或查询参数取得操作者身份。
- 复验方法：新增全路由“默认拒绝匿名”清单测试；为任务、班级、训练和报告补充跨学生、跨教师、跨学校的 401/403/404 测试；确认拒绝事件写入真实资源编号。
- Claude Code 状态：待独立复核。

### AUTH-102｜当前认证边界测试无法发现漏加认证的接口

- 链路：身份、角色与对象归属
- 类型：事实
- 严重级别：P1
- 证据：`tests/unit/test_auth_boundary.py:29-32` 能识别认证依赖，但 `60-76` 在收集测试对象时主动跳过没有认证依赖的路由；`186-197` 只验证已进入该列表的接口返回 401。
- 影响：新增或已有接口漏加认证时不会进入测试矩阵，全量测试仍可通过；这解释了 147 项定向测试通过与 AUTH-101 同时成立。
- 最小修复方向：维护显式公开路由白名单，测试应断言所有其他业务路由都带认证依赖，再逐项验证无令牌结果。
- 复验方法：临时增加一个未认证非公开测试路由时门禁必须失败；恢复后所有非公开路由无令牌均返回 401。
- Claude Code 状态：待独立复核。

### AUTH-103｜机器人私有或未发布资产可被匿名列出和下载

- 链路：身份、角色与对象归属
- 类型：事实
- 严重级别：P1
- 证据：`app/api/v1/endpoints/robots.py:498-582` 的工具、资产清单和任意资产路径下载均无认证、所有权或发布状态校验；下载入口仅确认机器人存在和文件存在。注释以浏览器加载器不能附加令牌为由将全部 GLB/JSON 归为非敏感，但列表同时返回存储路径，下载入口也没有限制到已发布资产类型。
- 影响：上传中的模型、清单或其他存储文件可能被枚举和获取，跨教师、跨学校隔离无法证明。
- 最小修复方向：将公开发布资产与私有上传分开；公开入口只接受不可猜测的发布标识并校验 `READY/published` 状态，私有清单和源文件继续使用认证与对象归属校验。
- 复验方法：匿名只能读取明确发布的模型；草稿、处理失败、其他教师或其他学校资产返回 404；资产列表必须要求认证。
- Claude Code 状态：待独立复核。

### AUTH-104｜客户端身份头可决定权限分支和审计操作者

- 链路：身份、角色与对象归属
- 类型：事实
- 严重级别：P1
- 证据：
  - `app/api/v1/endpoints/teaching_roster.py:94-138,146-175,357-439` 直接读取可伪造的 `X-RMOS-Role` 和 `X-User-ID`；缺少角色头时读操作不做范围限制，写操作也不会拒绝。
  - `app/services/access_control.py:20-24,37-67,70-101` 在没有显式操作者时从 `X-User-ID` 写入允许/拒绝审计。
- 影响：调用者可通过省略或伪造头绕过对象范围，并污染审计中的操作者身份。
- 最小修复方向：权限分支和审计身份只取自已验证令牌形成的服务端 `ActorContext`；客户端头只能作为非安全元数据，不能参与授权。
- 复验方法：伪造或省略身份头不能改变令牌角色和对象范围；审计操作者始终等于令牌主体。
- Claude Code 状态：待独立复核。

### CTRL-101｜故障注入和清除可匿名修改全局适配器

- 链路：任务与机器人控制
- 类型：事实
- 严重级别：P1
- 证据：`app/api/v1/endpoints/adapter.py:50-85` 的故障注入和清除入口无认证、审批或审计，直接调用 `AdapterFactory.get_adapter()`；`app/adapters/factory.py:47-108` 返回进程级单例。
- 能力边界：当前工厂只实现模拟适配器；`factory.py:91-96` 的 Gazebo 和真实适配器均明确 `NotImplementedError`。因此本项已确认会改变共享模拟状态，尚不能外推为已能控制真机。
- 影响：任何调用者都能改变所有用户共享的模拟机器人状态，干扰任务、教学和证据；未来若直接接入真实适配器会形成更高风险入口。
- 最小修复方向：写入口要求认证、教师或管理员权限、目标机器人归属、明确风险级别、审批和审计；模拟故障入口应与生产入口隔离并默认关闭。
- 复验方法：匿名和学生请求被拒绝并留审计；教师只能修改授权机器人；审批、命令和结果使用同一追踪编号。
- Claude Code 状态：待独立复核。

### CTRL-102｜任务、执行记录和快照没有绑定具体机器人

- 链路：任务与机器人控制
- 类型：事实
- 严重级别：P1
- 证据：
  - `app/models/task.py:30-82`、`app/models/task_execution.py:8-20` 和 `app/models/snapshot.py:10-31` 均没有 `robot_id`。
  - `app/services/snapshot_service.py:29-85` 只接收任务和步骤编号，从全局单例适配器采集状态。
  - `app/adapters/factory.py:47-108` 只维护一个适配器实例，并从固定 `DEFAULT_ROBOT_MODEL_ID` 加载配置。
- 影响：无法证明一所学校五台机器人之间的任务分配、状态、快照和控制互不串线，也无法完整追溯报告中的证据来自哪台机器人。
- 最小修复方向：在任务、执行和快照链中建立不可变的机器人绑定，并让适配器注册表按机器人编号隔离连接与状态；这会触发数据结构和架构决策，必须在修复阶段另行确认并写 ADR。
- 复验方法：两台机器人并行执行时，命令、快照、事件和报告只出现各自机器人编号；跨机器人访问和订阅均被服务端拒绝。
- Claude Code 状态：待独立复核。

### CTRL-103｜执行前设备和工具检查在缺少关键输入时放行

- 链路：任务与机器人控制
- 类型：事实
- 严重级别：P1
- 证据：
  - `app/api/v1/endpoints/tasks.py:42-50` 创建任务时把 `robot_id` 固定为 `None`，且不提供实际可用工具清单。
  - `app/services/preflight_check.py:193-200` 在没有机器人编号时直接 PASS。
  - 同文件 `228-237` 没有读取适配器或设备锁，直接把在线、未锁定、非维护写成正常结果。
  - 同文件 `276-315` 仅在 `available_tools` 已是列表时检查短缺；调用方未提供时，即使 SOP 声明了所需工具也返回 PASS。
- 影响：执行前检查的绿色结果不能证明设备在线、未占用、非维护或工具齐全；违反 G2，不能作为真机开工门禁。
- 最小修复方向：机器人编号和实时可用状态缺失时默认阻断；工具库存未知时不得写“全部可用”；将检查结果绑定到任务和机器人并设置短时有效期。
- 复验方法：缺机器人、离线、被占用、维护中、工具状态未知或缺工具均阻断；只有来自授权机器人的新鲜状态才能通过。
- Claude Code 状态：待独立复核。

### CTRL-104｜对外任务生命周期没有取消或紧急停止入口

- 链路：任务与机器人控制
- 类型：事实
- 严重级别：P1
- 证据：`app/models/task.py:11-27` 定义了 `CANCELLED`，但 `app/api/v1/endpoints/tasks.py:31-262` 只提供开始、步骤、暂停和恢复。对应用路由和服务检索 `cancel_task`、`stop_task`、`TaskStatus.CANCELLED` 未找到实际停止路径；`emergency_stop` 只存在于模拟执行器和模拟适配器内部。
- 影响：发生危险、误操作、人员离场或网络异常时，没有可审计、可授权、可验证的统一停止流程；违反 G5。
- 最小修复方向：设计独立于普通业务流的停止通道，明确认证、权限、机器人绑定、幂等、超时、失败升级和审计；真机还必须验证现场硬件急停，软件停止不能替代它。
- 复验方法：进行中和暂停任务均可幂等停止；重复请求不产生重复动作；断网或服务故障时现场急停仍有效；E3 前完成真机演练。
- Claude Code 状态：待独立复核。

### CTRL-105｜并发步骤提交可能重复写入事件和快照

- 链路：任务与机器人控制
- 类型：推断
- 严重级别：P2
- 证据：`app/services/task_service.py:93-304` 读取 `current_step_index` 后创建事件和快照，最后才更新并提交；未看到行锁、版本号、幂等键或唯一约束。两个并发请求可能同时读取同一进度并各自通过顺序判断。
- 影响：可能形成重复事件、重复快照或进度覆盖，进而污染评分和报告。当前没有专项并发测试，因此不能登记为已复现事实。

- 复验方法：对同一任务同一步骤并发提交至少 20 轮；每轮最多一个成功副作用，事件、快照和进度保持唯一一致。
- Claude Code 状态：待独立复核。
