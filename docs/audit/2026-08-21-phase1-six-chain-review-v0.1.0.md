## 1. 证据和严重级别

- **事实**：可由当前代码、配置、测试输出或可复现命令直接确认。
- **推断**：代码形态显示存在风险，但尚缺少专门测试或运行证据。
- **未知**：当前材料不能作出结论，必须补充环境、真机或专项演练。
- **P0**：未修复前不得通过 E1，存在直接越权、绕过关键安全门禁或不可接受的数据/控制暴露。
- **P1**：上线或高风险使用前必须修复，当前设计不能满足既定安全、隔离或恢复要求。
- **P2**：需要进入后续修复计划，影响完整性、隐私、稳定性或测试可信度。
- **P3**：低风险质量问题或改进建议。

## 4. 第一批发现：身份、对象归属与控制

### AUTH-101｜关键任务和教学接口可绕过令牌认证

- 链路：身份、角色与对象归属
- 类型：事实
- 严重级别：P0
- 证据：路由清单脚本递归检查 `get_current_actor` 依赖，当前 `/api/v1` 下有 109 个读写路由未声明该依赖。这个数字包含明确公开接口，因此不能把 109 个全部称为漏洞；但代表性高影响非公开入口已由代码确认。
- 代码证据：
  - `app/api/v1/endpoints/tasks.py:31-110,142-262`：创建、开始、执行步骤、暂停、恢复、详情、报告和事件均不要求当前用户；只有列表入口在 `113-139` 使用认证身份。
  - `app/api/v1/endpoints/student_tasks.py:39-67`：调用方可直接传入任意 `student_id` 读取任务执行记录。
  - `app/api/v1/endpoints/teaching_roster.py:61-84`：班级列表和创建入口无认证；同文件大量课程、作业、尝试入口也采用相同模式。
  - `app/api/v1/endpoints/training.py:290-333`：强制提交直接信任请求体中的 `teacher_id`，可用被冒用的教师编号通过班级范围检查并写入审计。
- 影响：未登录调用者可读取他人任务和报告，或改变任务、课堂、训练状态；违反 G1 和 G2。
- 最小修复方向：建立明确的公开路由白名单，其余 `/api/v1` 路由默认要求服务端令牌身份；所有对象读写必须用认证身份做学生、教师、学校和资源归属校验，禁止从请求体或查询参数取得操作者身份。
- 复验方法：新增全路由“默认拒绝匿名”清单测试；为任务、班级、训练和报告补充跨学生、跨教师、跨学校的 401/403/404 测试；确认拒绝事件写入真实资源编号。
- Claude Code 状态：两轮确认。

### AUTH-103｜机器人私有或未发布资产可被匿名列出和下载

- 链路：身份、角色与对象归属
- 类型：事实
- 严重级别：P1
- 证据：`app/api/v1/endpoints/robots.py:498-582` 的工具、资产清单和任意资产路径下载均无认证、所有权或发布状态校验；下载入口仅确认机器人存在和文件存在。注释以浏览器加载器不能附加令牌为由将全部 GLB/JSON 归为非敏感，但列表同时返回存储路径，下载入口也没有限制到已发布资产类型。

### AUTH-105｜登录入口没有失败次数限制或临时锁定

- 链路：身份、角色与对象归属
- 类型：事实；由 Claude Code 第一轮提出，Codex 已独立核对
- 严重级别：P2
- 证据：`app/api/v1/endpoints/auth.py:197-262` 对错误密码只返回统一 401，没有记录失败次数、设置账号或来源限制、临时锁定或递增延迟；`app/core/config.py`、`docker-compose.yml` 和 `r-mos-frontend/nginx.conf` 也没有登录限流配置。`tests/unit/test_auth_api.py:156-191` 只覆盖单次错误密码和未知用户，没有连续失败门禁测试。
- 正向边界：未知账号和错误密码返回相同错误，避免直接暴露账号是否存在；密码校验本身使用哈希计算。当前缺口是没有限制持续自动尝试。
- 影响：可对固定账号持续尝试密码，增加凭据填充和暴力破解风险；属于认证入口的独立防护缺口。
- 最小修复方向：在可信服务端或生产入口建立按账号与来源组合的速率限制、短时锁定和可审计告警；避免永久锁定被用于拒绝服务，阈值和恢复方式需形成安全决策。
- 复验方法：固定账号连续错误登录达到阈值后返回明确的受限状态并写审计；换来源不能无限绕过，等待窗口后可安全恢复，正常登录不受明显影响。
- Claude Code 状态：两轮确认；第一轮提出并由 Codex 独立采纳。

### RT-102｜客户端心跳回包没有进入连接管理器

- 链路：遥测与实时通道
- 类型：事实
- 严重级别：P1
- 证据：前端 `src/hooks/useWebSocket.ts:128-137` 收到 ping 后发送 `{"type":"pong"}`；后端 `app/api/v1/endpoints/websocket.py:28-34` 只读取并记录消息，没有调用已经存在的 `ConnectionManager.handle_client_message`。管理器 `app/services/websocket_manager.py:82-137` 因而不会更新 `last_pong`，约 60 秒后把连接标成不健康，遥测循环随后跳过该连接，累计三次后再关闭。
- 影响：正常客户端也可能在连接仍显示存在时停止收到数据，之后被服务端断开；课堂实时监控和故障诊断会出现可重复的假离线。

- 复验方法：用可控时钟连续运行超过四个心跳周期；有效 pong 保持健康和持续 5 Hz 推送，缺失 pong 才按阈值关闭，断开后连接与后台任务均清理。
- Claude Code 状态：两轮确认。
