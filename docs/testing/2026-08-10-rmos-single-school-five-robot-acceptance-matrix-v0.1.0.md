## 1. 完成标准与判定规则

Phase 4.1仅在以下条件同时满足时完成：

- AC-01至AC-10全部有验证方法、负责人、证据和Pass/Fail标准。
- T-01至T-16各有正常、边界、异常3类用例，共48个用例。
- 每条AC至少包含3组正常数据，并覆盖最小值、最大值或临界值以及空值、伪造、越权、损坏或超限数据。
- 任一强制用例失败，则对应Test_ID和AC_ID均为FAIL；不得用平均值抵消安全或权限失败。
- 真机动作验收只允许预定义动作，必须逐次教师确认、现场安全检查和物理急停有效；AI直接控制真机出现1次即FAIL。
- 每次正式执行必须保存原始数据、时间、版本、操作者、环境、结果和校验值；缺任一项，证据包为FAIL。

统一结果只有两种：

- **PASS：** 用例的全部成功条件均满足，且证据齐全。
- **FAIL：** 任一成功条件不满足、执行被绕过、数据不完整或证据缺失。

证据保存路径统一为：`evidence/acceptance/<run_id>/<case_id>/`。`run_id`格式为`YYYYMMDD-HHMM-版本-环境`。每个目录至少包含：

1. `manifest.json`：用例、版本、环境、操作者、开始和结束时间、结果。
2. 原始请求、响应、日志、审计或遥测数据；真机测试另含连续录像和厂家检查表。
3. `checksums.sha256`：证据文件校验值。
4. `result.md`：逐条判定和失败原因；不得只写“看起来正常”。
