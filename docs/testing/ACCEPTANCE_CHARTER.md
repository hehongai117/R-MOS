# R-MOS 验收章程

- 版本：0.1.0
- 生效日期：2026-08-21
- 状态：Active
- 适用范围：R-MOS 的代码、测试、文档、配置、数据、部署和真机交付变更

## 1. 目的与关系

本章程只定义一件事：什么条件满足时，R-MOS 的一项变更才可以写成“通过”。

- `AGENTS.md` 是最高工作规则。
- 本章程定义验收裁决、证据等级和不可绕过的门禁。
- `docs/testing/2026-08-10-rmos-single-school-five-robot-acceptance-matrix-v0.1.0.md` 定义单校五台真机交付的 10 条验收条件和 48 项详细测试。
- `docs/plans/2026-08-10-rmos-single-school-five-robot-deployment-rollback-v0.1.0.md` 定义 `REL-BLOCK-01`、`DR-01` 至 `DR-06` 和生产启用阻断。
- `docs/testing/TEST_PLAN.md` 是测试覆盖清单，不是当前执行结果。
- `docs/testing/TEST_REPORT.md` 保存当前提交上的实际执行结果。
- `docs-archive/DEVELOPMENT_LOG.md` 保存每批变更的命令、结果、失败处理和下一步。
- `docs-archive/` 与 Git 历史只作为历史证据，不能自动证明当前状态。

## 2. 验收状态

每个验收点必须明确写成以下一种状态：

| 状态 | 含义 |
|---|---|
| NOT_RUN | 尚未执行，默认状态 |
| PASS | 在指定提交和环境实际执行，全部二元标准满足且证据完整 |
| FAIL | 已执行，但至少一项标准不满足 |
| BLOCKED | 缺少环境、数据、设备、权限或外部条件，无法完成执行 |
| N/A | 当前变更确实不适用，且已写明理由和替代检查 |
| HISTORICAL | 只记录过去某个提交或环境的结果，不代表当前通过 |

“设计完成”“服务启动”“固定样本成功”“人工走过部分流程”和“历史测试全绿”均不能单独写成当前 PASS。“有条件通过”不能替代总体验收结果；存在未满足的强制项时，总体状态只能是 FAIL 或 BLOCKED。

## 3. 证据等级

| 等级 | 证据 | 允许支持的结论 |
|---|---|---|
| E0 | 计划、说明、注释、历史报告 | 说明目标、范围或历史状态 |
| E1 | 当前静态代码、配置、数据结构、Git 历史和自动化测试 | 支持当前软件结构和受测路径结论 |
| E2 | 与交付配置一致的预生产测试、浏览器流程、性能、断网和恢复演练 | 支持预生产非功能门禁结论 |
| E3 | 真实机器人安全区内的连续运行、故障注入、动作和急停证据 | 支持真机资格结论 |
| E4 | 真实课堂试点记录 | 支持课堂交付结论 |

低等级证据不能代替高等级证据。任何结果都必须绑定提交、环境、命令或操作路径、原始输出及执行时间。

## 4. 不可绕过的门禁

### G1：身份、角色与对象归属

- 所有非公开接口和实时通道都必须认证。
- 角色权限和对象归属必须同时成立；跨学生、跨班、跨教师、跨学校和跨机器人访问必须拒绝。
- 越权读取对外返回 404，越权写入返回 403；两者都必须记录真实资源编号和拒绝原因。
- WebSocket 必须按机器人和订阅权限隔离，跨机器人消息必须为 0。

### G2：写操作、审批与审计

- 任意有副作用的工具或动作，风险等级不得低于 medium，并从教师确认开始走审批。
- critical 操作必须遵守对应方案中更严格的多人确认要求，不得降级。
- 未审批、过期审批、状态已变化、学生自批或伪造审批均不得执行。
- 命令、工具调用、批准、执行结果和审计必须由同一 `trace_id` 串联。
- 拒绝、失败和超时与成功一样必须保留审计。

### G3：证据、评分与报告一致性

- 引用和证据必须由服务端验证存在、完整且调用者可访问。
- 证据、步骤结果、评分快照和报告必须属于同一训练或任务对象。
- 缺失、损坏、越权或归属错误的证据不得用于完成步骤、冻结成绩或发布报告。
- 已发布报告不得悄然随底层数据变化；变更必须形成可追溯版本。

### G4：AI 边界

- AI 可以解释、检索和生成草稿，不得直接控制真实机器人。
- AI 直接真机动作、绕过审批写入和越权写入的允许次数均为 0。
- RAG 对象级后过滤返回空属于检索行为；HTTP 越权读取仍按 G1 返回 404。
- AI 不可用时必须安全降级，核心教学与停止能力不能依赖外部 AI。

### G5：真实机器人安全

- 只允许预定义动作；每次动作都需要教师确认、现场安全检查和有效物理急停。
- 状态不明、响应超时或断网后不得自动重发动作。
- 厂家资料、围栏、急停、复位和回零检查缺任一项，机器人都不得进入受控运行。

### G6：生产启用与恢复

- 单元测试、服务启动、桌面推演和模拟机器人不能替代预生产恢复或真机演练。
- `docs/plans/2026-08-10-rmos-single-school-five-robot-deployment-rollback-v0.1.0.md` 中的 `REL-BLOCK-01` 持续有效：`DR-01` 至 `DR-06` 未全部真实 PASS 前，阻断 D0 和任何生产启用。
- 没有 E2、E3、E4 对应证据，不得宣称预生产、真机或课堂交付通过。

## 5. 按变更类型执行的最小验证

| 变更类型 | 最小验证 |
|---|---|
| 仅文档 | 链接、编号、版本、路径、规则一致性和差异检查 |
| 后端逻辑 | 相关单元或集成测试；涉及接口时验证状态码、身份、对象归属和审计 |
| 前端逻辑 | 相关 Vitest；影响构建时执行构建；影响真实交互时执行浏览器流程 |
| 数据或迁移 | 升级、兼容、回滚和数据一致性检查；跨模块影响按规则补 ADR |
| 权限、审批、AI 或审计 | 正常、边界、异常和越权用例；拒绝审计与零次阈值必须实际验证 |
| WebSocket 或遥测 | 连接认证、订阅授权、跨机器人隔离、断线和重连检查 |
| 真机或发布 | 对应 E2/E3/E4 门禁、厂家安全项、连续录像、恢复和回滚证据 |

测试范围必须与风险匹配。只运行较小测试集时，只能对该范围作结论；不得外推成全量回归、整条链路或生产通过。

## 6. 证据记录

每批任务必须在 `docs-archive/DEVELOPMENT_LOG.md` 留下以下八个字段：

- DateTime
- Task
- Scope (files changed)
- Commands Run
- Tests
- Result
- Risks/Notes
- Next Step

影响验收的任务还必须在 `docs/testing/TEST_REPORT.md` 记录：

- Test ID 或门禁编号；
- 提交号和执行环境；
- 命令或人工操作路径；
- 关键原始输出和证据位置；
- PASS、FAIL、BLOCKED、N/A 或 HISTORICAL；
- 失败原因、处理动作和复验结果。

证据不得只存在于聊天中，也不得把计划中的期望输出写成实际结果。

## 7. N/A 与阻塞处理

N/A 只有在以下条件同时满足时才有效：

1. 当前变更确实不触及该验收点；
2. 写明不适用原因；
3. 给出替代检查或说明为什么无需替代；
4. 在测试计划、当前报告和开发记录中保持一致。

缺少环境、服务、测试数据、预生产、机器人或课堂时必须写 BLOCKED，不得写 N/A 或 PASS。阻塞解除后必须在同一提交或新提交上重新执行。

## 8. 与现有测试材料的裁决关系

- 单校五台真机验收矩阵中的 AC-01 至 AC-10、T-01 至 T-16 及 48 项正常、边界、异常用例继续有效；其中标为待 E1/E2/E3/E4 的项目仍是 NOT_RUN 或 BLOCKED。
- `docs/specs/ACCEPTANCE_TEST_MATRIX.md` 是早期 v0.3 专项矩阵，只作为补充历史材料；其中仍有效的安全语义已纳入本章程。
- `docs/testing/TEST_PLAN.md` 中旧的“PASS”标签必须结合对应历史报告理解；没有当前提交证据时按 HISTORICAL 处理。
- 本章程与详细矩阵出现二义性时，先按更严格的安全要求停止执行，再同步修正文档；不得自行选择较宽松解释。

## 9. 当前生产结论

截至 2026-08-21，本章程和验收矩阵只完成规则与测试设计整理。本批没有执行 E1 至 E4 的正式验收，也没有清零 `REL-BLOCK-01`。

因此当前只允许得出以下结论：规则修复不等于软件验收，软件测试不等于真机验收，真机局部验证不等于生产启用。
