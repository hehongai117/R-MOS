# 领域校准说明：D-03/D-08 机器人资源与适配器（含安全）

- 冻结日期：2026-08-29
- 依据：章程 §7.6「每域首批 2 个样本后冻结领域校准说明」——本域已取 3 个样本
- 样本：ros2_control、Open-RMF、openTCS
- 状态：**REFROZEN（0.1.2）——已补 VDA 5050 与 OPC UA Robotics 两项标准类来源，待复核方确认饱和性**

## 发布模式

三者均为**生态型基础设施**，非应用产品：ROS 2 发行版节奏（ros2_control、Open-RMF）
或独立版本线（openTCS 6.x）。**不应以「近 12 个月发布次数」直接横排**——
ROS 生态项目的发布与 ROS 发行版绑定，节奏由上游决定。

## 合理贡献者规模

本域项目贡献者规模显著小于通用软件（Open-RMF 116 stars / openTCS 566 stars）。
**星标与贡献者数在本域不具区分度**，社区采用维度（5 分）应主要看
机构采用证据（Fraunhofer IML 之于 openTCS、OSRA/Open Robotics 之于 ROS 生态），
而非 GitHub 数字。

## 采用证据形态

工业 AGV/机器人中间件的采用证据多为**厂商集成清单与研究机构背书**，
而非公开生产案例博客。缺少后者不应扣分。

## 本域的关键校准结论：三种范式，不可互斥评分

三个样本对「适配器契约如何表达控制与停止」给出**三种不同答案**：

| 项目 | 范式 | 停止如何表达 |
|---|---|---|
| ros2_control | **生命周期 + 类型化错误** | 去激活 + on_error + 组内故障传播（**无契约级急停原语** [uncertain]） |
| Open-RMF | **状态枚举** | `MODE_EMERGENCY = 5` 作为一级状态常量 |
| openTCS | **命令队列 + 背压** | `clearCommandQueue()` 清空在途命令 |

**这三者不是竞品，是同一问题的三个正交切面。**
因此本域**不产出单一「主参考」排名**，改为产出**契约要素合成表**（见 decision-matrix.md）。
按章程 §7.8，「零个合格主参考」是允许的正式结论；本域的情况是
「**多个合格参考、但不应二选一**」，同样记为正式结论。

## 对评分模型的本域调整

- 「业务与规模匹配」25 分：三者的部署形态（ROS 2 运行时 / JVM 全栈）**都与 R-MOS 不匹配**，
  但拟采用方式是「只借设计」，该维度应按**设计可迁移性**而非部署匹配度评分，否则三者同时低分而失去区分意义。
- 「引入与迁移成本」10 分：同理，按「读懂设计并在 Python 中等价表达的成本」评，不按部署成本评。
- 上述两条调整**仅适用于本域且仅适用于「只借设计」这一使用方式**，不得外推到其他域。
