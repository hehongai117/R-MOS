### 1.2 R-MOS 当前契约（对照基线）

`app/adapters/base.py` 的 `BaseRobotAdapter` 共 **10 个抽象方法**：

```
connect / disconnect / is_connected
get_robot_info / get_robot_structure / get_joint_states / get_sensor_data
inject_fault / clear_fault / get_active_faults
```

**分类：连接 3、读取 4、故障注入 3。运动控制 0，停止/急停 0。**
这是 M-07「适配器契约无运动控制与急停」的精确形态。

### 1.3.1 C-0：急停的最小正确模型（P0，取代原 C-1+C-2）

补研 VDA 5050 与 OPC UA Robotics 后，C-0 从「六步序列」扩为**结构 + 序列**两部分。

#### (a) 结构：急停不是一个布尔

| 要素 | 来源 | 说明 |
|---|---|---|
| **急停 vs 防护性停止分开建模** | OPC UA Robotics §7.8/§7.9（依 ISO 10218-1 §5.5.2/§5.5.3） | 人主动触发 vs 防护装置触发；解除条件、优先级、责任方都不同 |
| **安全状态是具名功能实例的聚合** | OPC UA `SafetyStateType` | `EmergencyStop = OR(各 EmergencyStopFunction.Active)`，每个实例带 `Name`。**才能回答「是哪一个急停被触发」** |
| **急停按解除权限分型** | VDA 5050 `EStop`：AUTOACK / MANUAL / REMOTE | 解除权限是急停类型的**固有属性**，不是全局设置 |
| **运行状态机 / 停止方法 / 安全状态三者分离** | OPC UA §7.10 / §7.16.8 / §7.7 | 不应混进一个枚举 |

> **五个候选里，只有 OPC UA Robotics 给出「急停 vs 防护性停止」的区分。**
> Open-RMF 的单一 `MODE_EMERGENCY` 会把两者压平——这是 C-1 判定为 PARTIAL 的根本原因。

#### (b) 序列：停止是一个带确认的过程

1. **急停状态锁定**（latch，不因后续事件自动解除）
2. **拒绝新动作**
3. **使未发送动作失效**（openTCS `clearCommandQueue` 只覆盖到这一步）
4. **向控制器下发取消/停止**——VDA 5050 的 `cancelOrder` instantAction 是其标准形态
5. **等待并记录逐动作确认**：VDA 5050 要求被取消的动作**显式报 `FAILED`**，
   调用方据此知道「取消进行到哪一步」
6. **按急停类型所要求的权限解除**（自动确认 / 车端手动 / 远程），非全局解除

> **第 4、5 步是 0.1.0 完全缺失的**，正是被「清队列即停止」这个误读掩盖掉的部分。
> VDA 5050 的 `cancelOrder` 给出了这两步的成熟形态：**取消是下发到设备、带逐动作状态反馈的过程**。

#### (c) 边界：软件契约不构成安全功能

- **VDA 5050 明确声明自身不是安全标准。**
- **OPC UA Robotics 的规范依据是 ISO 10218-1**——权威在标准，不在任何开源项目。

**因此 R-MOS 的适配器契约无论做得多完备，作用都是*表达*与*上报*安全状态，不是*构成*安全功能。**
这直接回答 R1-Q1：急停的权威层在物理安全回路与 ISO 10218-1，软件层只负责表达、拒绝与留痕。

### 1.4 借什么 / 不借什么

**借（设计层）：** C-0（P0）、C-3~C-9 按上表订正后的表述。

**明确不借：**

| 不借 | 理由 |
|---|---|
| ROS 2 / JVM 运行时与消息模型 | 技术栈与规模不符 |
| 实时性设计、交通调度、路网模型 | R-MOS 无此需求 |
| **「ros2_control 有急停原语」** | 出处为演讲材料非契约文档，`[uncertain]` |
| **~~「清队列即停止」~~** | **0.1.0 的错误结论，已删除** |
| **C-9 用于急停** | 析构自动恢复，与急停的闩锁语义相反 |

### 1.5 失败模式（R1 必须避免）

1. **假急停 I**：只置状态位不做任何指令层动作。
2. **假急停 II（0.1.0 主审自己犯的）**：置状态位 + 清本地队列就认为停住了——
   **已送达控制器的命令不受此保证**，必须显式发取消并等确认。
3. **抄枚举不抄迁移规则**：定义了 `EMERGENCY` 却没定义谁能置位、置位后拒绝什么、如何解除。
4. **用自动恢复语义实现急停**：如直接套用 Open-RMF 的 `Interruption`（析构即恢复）。
5. **把业务通信协议当安全回路**：VDA 5050 明确声明自身不是安全标准。
