### 3.1 G1 是 M-14 的复发

`get_visible_robot_or_404` 是 M-03 时**专门提取出来的唯一实现**，HTTP 与 WS 共用。
本次发现**五个**按编号读取的端点（详情、分析任务、工具、资产清单、资产下载）
各自写了判定、绕过了它——规则又分叉了。

修法是让它们改走该函数，**不在端点里补等价判定**。已用 AST 断言固定该事实，
防止再次分叉。

顺带纠正返回码：读路径越权由 403 改为 **404**（不泄露存在性）。

### 3.2 一个容易漏的点

跨校修复中，**历史遗留的跨校绑定也不能穿透**。
只堵新建绑定是不够的——库里已有的跨校 `teacher_robot_bindings` 记录
会让越权继续生效。已有断言覆盖。

## 4. 产品语义变更：SHARED 收紧为校内共享

**这是本模块唯一一处改变产品能力的改动，已提请并获董事会裁定。**

| 项 | 内容 |
|---|---|
| 原语义 | 教师设为 SHARED 后，**全平台已认证用户**可见（含他校） |
| 新语义 | **仅同校可见**；`owner` 为空的系统内置 SHARED 仍全平台可用 |
| 裁定 | 董事会 2026-09-06：**保持现状（仅同校可见）** |
| 依据 | 与「跨校是租户边界」的既定口径一致——模块 F、C 已按此定过两次 |
| **承担的代价** | 教师间**跨校共享能力消失**；Phase 6 交付的「共享市场」（`SharedRobotsPage`）实际降为校内库 |

> 设计文档（`2026-05-07-multi-robot-platform-design.md`）写的是
> 「教师间可授权共享」「浏览共享机器人库」，**未明确是否跨校**——
> 该歧义由本裁定消解，方向为**校内**。
>
> 若将来需要跨校共享，应新增独立的可见性档（如 PRIVATE／SCHOOL／PUBLIC 三档），
> 而不是放宽 SHARED——放宽会同时打开租户边界。
