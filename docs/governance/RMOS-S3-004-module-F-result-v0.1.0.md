## 2. 缺陷处置

| 编号 | 内容 | 处置 |
|---|---|---|
| **F-AUTH-04** | 评分只核实教师是否在**任一**自有班级带过该学生，未绑定该尝试所属班级——教师 A 只要在自己某个班教过学生 X，就能给 X 在教师 B 班级的尝试打分 | ✅ **已修**：管辖权绑定到 `assignment.class_id` |
| **跨校班级可见** | `list_classes` 无身份注入、无过滤；`get_class` 教师分支无校验——他校教师可读任意班级 | ✅ **已修**：按班主任的 `school_name` 过滤 |
| **时间线无写入** | 三张表整组无应用写入路径，回放恒返回 `insufficient_data` | ✅ **已补**：尝试完成时由真实 `EvidenceLink` 落成时间线 |
| F-AUTH-01／02／03 | 同校但不带该班的教师可读他人班级的名单、作业、尝试与证据 | ⬜ **裁定为设计**（董事会 2026-09-06）——`ensure_user_scope` 文档明写「读规则允许同校教师，供教研与教务查看本校学生」。测试断言保留现状，不再当缺陷跟踪 |

### 2.1 跨校与同校的边界（本模块最容易混淆之处）

两者**必须分开看**，本次差点被合并处理：

- **同校**教师可读他人班级 → **设计**。院校场景的教研、代课、教务管理都需要
- **跨校**教师可读他人班级 → **缺陷**。学校是租户边界，不在上述设计意图内

修复时专门加了一条 `test_same_school_teacher_still_sees_classes`，
防止为堵跨校而误伤同校。

### 2.2 时间线写入的克制

裁决二要求「**先补写入再开放回放**」，顺序不可颠倒——无写入即无数据，
此时开放回放只会返回空结果，那正是「接口存在但能力不存在」。

写入实现刻意保守：**数据来源是该尝试真实的 `EvidenceLink`，不编造内容**。
没有证据就不建时间线，回放继续如实返回 `insufficient_data`。
有多少证据就回放多少，不用占位数据把接口"填绿"。
