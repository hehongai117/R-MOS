# ADR-2026-08-17：SOP 三段式引导数据结构

## 背景

Asimov-1 式三段引导改造需要为每个 SOP 步骤保存所属阶段、模块子装配路径、作者化 3D 构图和所需物料，同时必须保持现有 SOP 的行为不变。

## 决策

在既有 `sop_steps` 表新增 `phase`、`group_path`、`step_view`、`required_parts` 四列，不新建表。阶段值为 `prep`、`execute` 或 `verify`；构图和物料分别以 JSON 保存。

## 备选

1. 新建 `sop_phases` 与 `sop_step_views` 关联表：结构更细，但本次四个字段没有独立生命周期，增加查询与维护成本。
2. 全部塞进现有 `action_params` JSON：无需迁移，但字段缺少明确模型、接口和查询边界。

## 影响

后端 SOP 模型、接口对象和裁决格式映射器新增四个字段；前端后续将消费这些字段。现有 31 个 SOP 不需要内容修改，默认归入执行阶段。

## 迁移策略

`phase` 使用 `server_default="execute"`，使存量步骤在迁移时自动归入执行阶段，无需数据回填。其余三列允许为空，现有步骤保持原有行为。

## 回滚策略

执行 `alembic downgrade -1` 直接删除四列。存量数据不使用这些列，因此不会造成存量数据损失。
